# Markup round 0

`draft.md` holds ten sections of documentation for `codex-delegate`, written 2026-09-11.

## What to do

Edit `draft.md` in place, the way you would edit anything else. Change what you would change, delete
what you would delete, move what sits in the wrong order. Do not try to be systematic, and do not
explain yourself unless the edit alone will not say it — where it will not, leave an
`<!-- why -->` beside it.

A section passes if you close the file without having touched it.

## What this round measures

Not the pass rate. Ten sections give an interval almost as wide as the scale, and a rate needs several
rounds.

It measures **what kind of change you make**: wording, arrangement, what is included, or length. That
number decides whether a writing rule can move the pass rate at all. If most of what you change is what
the text covers and in what order, then no rule about phrasing will help, and finding that out now costs
one evening instead of five hours.

## How these were written

The way I write documentation when asked for it, with two deviations worth declaring, because a baseline
nobody can describe is not a baseline.

**One learned rule is applied.** Of the three factors the paired comparison screened, one separated:
across twelve decisive answers you chose the literal phrase over the figure of speech ten times, with no
ties. So these sections use the plain phrase wherever one exists. Everything else about them is my
default.

**The current README was not used as a source.** The sections are written from `driver.mjs --help-all`,
the reference files under `skills/seat/references/`, `skills/cleanup/SKILL.md`, `RELEASING.md` and
`evals/fidelity.test.mjs`. Passages of the README have passed through this session in other contexts, so
this is a claim about what I worked from, not about what I have never seen. The point is that you are
not being asked which of two versions is better — only whether you would ship this one.
